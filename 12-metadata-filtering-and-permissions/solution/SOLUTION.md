# Solution for Lesson 12: Metadata filtering and permissions

In the course's implementation as shipped, a missing roles field is a latent default allow hazard: the manifest is the only source of roles, and any loader that substitutes a permissive default (or a chunker that treats empty as everyone) turns an administrative omission into a disclosure. The audit catches the omission (all_have_roles goes False) but the runtime path is where the guarantee must live. The correct patch is at load time: roles default to the empty set, so `role in chunk roles` is False for every role and the document is invisible everywhere, and the audit then surfaces the classification task instead of the leak. After the patch: Lesson 02 reports the document but flags roles incomplete; this lesson's numbers are unchanged (the new document was public content but unclassified, so public counts do not move), and classifying it properly (adding roles: [public, staff, manager] per the course's convention) restores it deliberately, in a reviewed manifest edit, which is exactly the workflow the lesson argues for.
