# Solution for Lesson 20: Grounding and refusal

A narrow intent rule (refuse when the question matches a price match pattern: price, match, beat, competitor) takes refusal to 6 of 6 on the reference build with false refusals still 0, because no answerable golden question uses that intent. The maintenance implication is the graded answer: the day Fernhill adopts price matching and the policy enters the corpus, the blocklist silently refuses a now answerable question, and nothing in the refusal scorecard notices unless the golden set gains the new question the same week. Intent rules are therefore corpus coupled configuration: they belong in the same reviewed change as the document that obsoletes them, and the golden set must grow a question for every intent rule retired. Mechanisms that age silently are how refusal systems rot; the alternative, an entailment checking model, ages loudly instead (its errors are visible in answer level metrics), which is a real argument for it at scale.
